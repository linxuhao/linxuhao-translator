# H3 镜头提示词技法 · VideoMCP

本文件只放**跨作品为真**的东西:模型如何解析提示词、哪些写法可复现、哪些是接口硬约束。
某一部片的风格、审美否决与验收标准属于该项目的 brief 与导演笔记,**不写在这里**。
读本文件不启动生成,不改变项目或 GPU 状态。

## 1. 一条镜头提示词的结构

五段,按此顺序写:

```
主体与环境 → 动作及其随时间的变化 → 摄影机运动 → 光照与风格 → 声音
```

描述**这一个镜头里发生了什么**。短提示词给模型更多自由,长提示词给你更多控制;
控制力来自具体,不来自堆砌。

## 2. 身份锚定:每个镜头逐字重复外观属性

模型不会因为你写了"同一个人""他""the same couple"就在镜头之间保持身份。
**代词与回指在镜头边界上不成立。**

每个镜头中,对每个出场主体,**逐字重复同样 3–6 条可区分的外观属性**。

- 选属性的标准是:**可见、稳定、可区分**。发型与发色、标志性衣物及其颜色、
  体型与年龄段、随身道具。
- **不要把表情、视线方向、睁眼幅度写进锚定短语。** 那些是表演,每个镜头都该不同;
  把它们锁进身份描述,得到的就是一张跨镜头不变的僵脸。
- 同一项目中同一主体的锚定短语应当**逐字一致**。把它存在 `project.characters`
  的 `anchor_phrase` 里,每次复制粘贴,不要凭记忆复述——改写即失锚。
- 身份锚定与参考图是**两条独立的通道**,同时用。参考图给外观,锚定短语告诉模型
  该跟随哪一个主体;只给参考图不写锚定,多主体镜头容易串脸。

```
弱:  The same couple walk away hand in hand.
强:  The woman in the ivory knit sweater and the man in the navy coat
     walk away hand in hand.
```

> 本条尚未在本部署做过对照实验。先按此写;A/B(同镜同 seed,一版代词一版锚定)
> 出结果后再决定是否升级为硬规则。

## 3. 动作要可演:写可见行为,不写内在状态

情绪形容词不约束像素。把情绪换成**产生这个情绪的可见证据**。

```
弱:  一个悲伤的人
强:  泪痕挂在脸颊,肩膀塌下,盯着一把空椅子
```

一个镜头有一个主导动作,但"一个动作"**包含**自然的准备、执行、接触、跟进与反应——
不要把它误解为只许动一下手或转一下眼珠。

给主体一个**具体任务**,而不是一个状态:挡开伸过来的手、扶稳快要倒的东西、
接住落下的物件、看一眼再作出回应。有任务才有可演的东西。

**当镜头里没有表演主体时**(风景、静物、产品、抽象),这一节换成另一条标准:
画面中的变化——主体运动、摄影机运动、光线或材质的变化——必须有来由且可信。
不动的镜头是合法的镜头;**无来由地动**才是问题。

## 4. "静止"是一个严格的词

静止镜头意味着零位移、零焦点变化、零推拉。只要其中任何一项会发生,
就不要写"静止镜头",改用准确的运动原语(推、拉、横移、跟随、升降、手持)。
含糊的"static"会让模型在该动时不动、在不该动时乱动。

## 5. 声音

H3 的 FL2VA / Ref2VA 同时生成画面与声音。按四类描述,只写这个镜头里**听得见**的东西:

- **环境声**:风、雨、车流、人声嗡鸣、鸟鸣、机械嗡响
- **动作声**:脚步、开门、衣料摩擦、器物碰撞
- **人声质地**:耳语、平静叙述、高声呼喊
- **音乐情绪**:仅当这个镜头内确实应当有音乐时才写

对白写进引号。不要写"电影级音效"这类不约束任何东西的词。

> 成片的配乐、旁白与声场衔接属于**剪辑阶段**,不靠在每个镜头提示词里写"背景音乐"来实现——
> 那只会得到每镜一次重启的音乐。

## 6. 只写画面,不写制作指令

不要把分辨率、步数、seed、档位、审批状态、流程说明写进提示词。
**不要虚构 `negative_prompt` 或任何接口未暴露的参数**——它们不会生效,
只会挤占编码预算。

## 7. 接口硬约束

- 编码器每次 conditioning 上限 **4096 token,含图像 token**;超出直接拒绝。
- `prompt` 字段上限 **12000 字符**。
- `references`(1–4 张,有序)走 **Ref2VA**;`image` / `last_frame` 走 **FL2VA**;
  **二者不可混用**;都不提供即文生视频。
- 多参考图按顺序对应提示词中的 Picture 1、Picture 2 ……
- 画布:`preview` 608×352,`768p` 1344×768;`frames` 为 17k+5,22–124,24fps。
  两种画布宽高比不同,**不能笼统当作同一个 16:9**。

## 8. 提示词与条件图的分工

条件图承载**外观与构图**;提示词承载**动作、时间变化与摄影机**。

一个属性即使已由参考图确定,提示词里仍要用锚定短语点名它(模型需要知道跟随哪个主体),
但不要用提示词去覆盖参考图已经定下的构图。

**不要用提示词修补条件图的问题。** 图的构图、画幅或预处理错了,就换图重做——
在提示词里加描述去对抗一张错的条件图,是在花钱买不可复现的结果。
排查顺序:原图 → 画幅预处理 → 实际送入的 conditioning → 提示词,
最后才轮到步数、档位与硬件。
